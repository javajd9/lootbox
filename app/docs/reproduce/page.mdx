# Reproduce a draw

Anyone can re-run a LOOTBOX draw from public data and check they get the same winner. This page explains how.

## What you need

| Input | Where it comes from |
|---|---|
| Every snapshot for the drop | Published as JSON on the drop's proof page. Each file's SHA-256 is posted on Solana when it's taken. |
| The locked ticket list's fingerprint | A Solana transaction posted before randomness was requested |
| The randomness | The drop's ORAO VRF request account on Solana (64 bytes) |

## Steps

1. **Check the snapshots.** Hash each snapshot file (SHA-256 over its canonical JSON, keys sorted) and confirm it matches the fingerprint posted on Solana at that time.
2. **Rebuild the ticket list.** For each wallet, average its balance across the snapshots, then divide by the per-ticket amount and round down. Remove excluded wallets, and any address off the ed25519 curve (owned by a program, so it can't sign). Sort by wallet address.
3. **Check the lock.** Hash the ticket list and confirm it matches the fingerprint posted before the randomness request.
4. **Pick.** Run the selection with the VRF's 64 bytes, as below.
5. **Compare.** The ticket and wallet you get must match the published winner.

## The selection, exactly

```text
total  = sum of all tickets
r      = the 64 VRF bytes, read as a big-endian 512-bit number
limit  = 2^512 - (2^512 mod total)
round  = 0
while r >= limit:
    round += 1
    r = SHA-512(vrf_bytes || round as 2 bytes)   # re-hash, try again
index  = r mod total                              # 0-based
ticket = index + 1                                # the number shown on the live page
winner = the wallet whose ticket range contains ticket
```
