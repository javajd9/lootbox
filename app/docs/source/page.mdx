## The docs come from the code

The rules on these pages aren't copied by hand. Each **Rule** box, the ticket size, the claim window and the drop queue are read from the same settings the engine runs on. The examples are made by the real code when the site is built: the [claim message](/docs/claiming), the [proof package](/docs/proofs), the [address fingerprint](/docs/privacy) and the [draw example](/docs/reproduce). If the code changes, these pages change with it.

## Run the tests

The tests run the drop engine from a drop opening to the winner's receipt, along with the ticket math, the draw, claims, orders and proofs. They need no keys or accounts. With Node.js 20 or later:

```bash
git clone https://github.com/javajd9/lootbox.git
cd lootbox
npm ci
npm test
```

## What the code can't show

Reading the code tells you what LOOTBOX is built to do. It can't prove that the server is running exactly this code. That's why every step also leaves evidence you can check without trusting the server: transactions and fingerprints on Solana, and zkTLS proofs from the order service. See [What you're trusting](/docs/trust) and [Verify it yourself](/docs/verify).
