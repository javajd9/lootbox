# How the winner is picked

The draw starts once a prize pool fills. It happens in four steps, and their order is what keeps it fair.

## Why it can't be rigged

The ticket list's fingerprint is on Solana before the randomness is requested. Adding, removing or moving a ticket after that would no longer match the fingerprint.

LOOTBOX can't choose or predict the random number. ORAO VRF produces it with a cryptographic proof that it wasn't tampered with, and that proof can be checked on-chain.

The math that turns the number into a ticket is public and deterministic, so the same list and the same number always give the same winner. You can [reproduce a draw](/docs/reproduce) yourself.

The rolling ticket on the live page only reveals a result that's already on-chain. It doesn't pick anything.

## How a random number becomes a ticket

1. Tickets are numbered in order of wallet address. If the first wallet holds 40 tickets, it owns #1–#40, the next wallet starts at #41, and so on.
2. ORAO VRF returns 64 random bytes, read as one very large number.
3. That number is mapped onto the ticket range with **rejection sampling**. If it lands in the small leftover zone that would favor low ticket numbers, it's re-hashed and tried again, so every ticket has exactly the same chance.
4. The resulting ticket number belongs to exactly one wallet, and that wallet wins.

## If something goes wrong

If the randomness request fails, it's sent again. The ticket list is already locked, so a retry can't change who's in the draw.
