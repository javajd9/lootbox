# Verify it yourself

The proof page runs most of these checks in your browser. This page explains each one so you can also run them by hand with your own tools.

## On the proof page

Open a drop's proof page and press **Verify everything**. Your browser checks the Paid transaction, the order, the delivery, the winner's receipt and the whole proof chain against the raw proof data and Solana itself. Nothing relies on a "verified" flag from our server. Once a drop has published proofs, **Try tampering** changes one number so you can watch a check fail.

The fee inflows and the draw are checked by hand, as described below. Everything you need is under **The raw data** on each drop's proof page.

## By hand, step by step

### 1. The chain and its fingerprints

1. Download the drop's **Proof packages** from its proof page (`/api/proofs/<drop>`).
2. For each package, compute SHA-256 over its canonical JSON (keys sorted, no whitespace).
3. Confirm each package's `prevHash` equals the previous package's fingerprint, and the first one's is `null`.
4. Open each package's `memo_tx` on Solscan. Its memo should read `LOOTBOX|v1|<drop>|<step>|<fingerprint>`, with the same fingerprint, signed by the proof publisher on [Addresses](/docs/addresses).

### 2. Funded and Paid

Look up the treasury on Solscan. Fee inflows should match the pool. The drop's Paid transaction should send at least the goal from the treasury to the purchasing account, with the drop's `funded` fingerprint in the same transaction.

### 3. Drawn

Follow [Reproduce a draw](/docs/reproduce), using the drop's **Draw data** (`/api/draws/<drop>`).

### 4. Ordered, Shipped, Delivered (zkTLS)

Each of these packages carries a Reclaim proof. Verify it with Reclaim's open-source SDK (`verifyProof` in `@reclaimprotocol/js-sdk`), then check:

- the proof's host is the order service (`api.zinc.com`), not some other server;
- the revealed fields match what the package says, such as products, order number or delivery status;
- the order's products match the drop's locked product list.

### 5. Received

The receipt is a plain message signed with the winning wallet's key (ed25519, signature in base58). Any Solana signature tool can check it. The message looks like this:

<CodeBlock label="Receipt message format">{receipt}</CodeBlock>

The `commitment` in the receipt is the address fingerprint from the **Claimed** step. By signing it, the winner confirms that this is the address the prize was sent to.

### 6. Your address (winners only)

If you won, enter your address and your secret code on the proof page. The fingerprint is recomputed in your browser and compared with the published one. See [Privacy](/docs/privacy) for the exact format.

## Which steps the proof page runs

On each drop's proof page, your browser runs steps 1, 2 (the Paid transaction), 4, 5 and 6. It reads each fingerprint from Solana's public RPC, checks each zkTLS proof's attestor signatures with Reclaim's SDK, and checks the receipt signature against the winning wallet. The fee inflows (step 2) and the draw (step 3) are checked by hand, from Solscan and the drop's **Draw data**.

The code your browser runs for those checks is public, so you can read exactly what it does, or copy it into your own script.
